## Топ-5

1. **№1 (К) — `media://` роняет всё приложение на файле ≥ 2 ГиБ.** `fd.read` с длиной > int32 — нативный assert, не исключение: ни `uncaughtException`, ни диалог «Pulsar остановился» не срабатывают, окно просто исчезает вместе с несохранённым проектом. Триггер — обычное действие: добавить длинный 4K-ролик в Монтаж/Шаблоны/Запись экрана (превью грузит файл целиком через `fetch().blob()`). Для файлов поменьше — гигабайтный буфер в памяти main на каждый клип. Чинится стримом (`createReadStream` → `Response`), полчаса работы.
2. **№15 (В) — анализ ритма не работает на реальных треках.** `res_type="kaiser_fast"` требует `resampy`, которого нет в современной librosa; любой MP3/WAV 44,1/48 кГц падает, приложение молча (теперь — с тостом) режет по сетке 0,5 с. Ключевая фича продукта («монтаж под бит») фактически выключена у всех, кто ставил librosa по инструкции. Фикс — одно слово в `beat_detect.py`, плюс добавить librosa в мастер установки.
3. **№3 (В) — Воронка перезаписывает результаты при не-латинских названиях.** `\w` без флага `u` превращает «Котик играет» и «Пёсик спит» в один и тот же `0__`; пачка русских/турецких роликов оставляет на диске один файл на ветку+язык, остальные затираются без предупреждения. Это потеря оплаченной работы (OpenRouter + дубляж на GPU).
4. **№2 + №16 (В) — текст с `%` не рендерится, шрифт игнорируется.** Заголовок Монтажа и текст VUB с процентом («Скидка 50%») экспортируются как пустая подложка — самый частый маркетинговый текст в нише. В VUB выбранный шрифт вообще не попадает в drawtext. Фикс — `expansion=none` и `fontfile`.
5. **№5 (В) — watch-папка VUB грузит main-процесс до 100 % CPU после удаления/переименования папки** (шторм событий `fs.watch`), а при ошибке watcher'а на сетевом диске — вероятный `uncaughtException` и выход. Следом по весу: №4 (дубляж/озвучка падают на немом видео), №7 (кандидат Python в Cleaner — всегда Store-заглушка первым), №9/№13 (отмена не убивает процессы: GPU и yt-dlp продолжают работать).
